# pic-ppt

以生图为主，忠实重构用户提供的PPT效果图。默认一张图对应一页，交付 `.pptx`：底图、各个线框、小图和图标是分开的图片对象，文字是原生可编辑文本框。图片可单独移动、替换及缩放，不宣称它们的内部线条可编辑。

## 核心约定

- 遵循用户指定顺序：**先底图，再逐个线框，再逐个小图/图标，最后文字排版与合成**。可以在开始时识别文字和位置，但先完成底图再制作前景素材。
- 保持原图的构图、层级、颜色分布、元素位置、文本内容和页面比例。高清重绘改善清晰度与边缘质量，不自行改版或增加装饰。
- **常见矩形框、圆角框、科技边框、线框插图等同样通过生图重绘**，不因形状简单就改用PPT原生形状、SVG或程序绘图拼出来。
- 不把整张效果图当作最终底图再盖一层文字；底图必须真正去除将被独立重建的前景与文字，避免双影。
- 不将整页重绘成一张图片充当成品，不把全部前景合并成一张透明图。每个独立元素对应独立图片对象。
- 已有清晰输入时直接开始，不增加大纲、风格、试做页等确认环节。只对影响内容准确性且无法从输入解决的问题请求澄清，其他可独立完成的部分继续做。

## 工具与文件

1. 使用当前环境的 `imagegen` 技能和内置 `image_gen` 工具处理补底、抠图和高清重绘；用户明确指定其他可用生图技能时按其选择。即使通用生图指南建议简单线框用矢量，本任务也遵循用户要求使用生图。
2. 查阅当次工具定义。对本地参考图先用图像查看工具检查，再按工具支持的方式传入实际参考图。仅在提示词中写本地文件路径不等于传入图片。
3. 每个不同素材独立生成并检查。对透明线框和抠出的图标明确设置 `transparent_background: true`；完整底图通常使用 `false`。生成多个素材不等于授权切换付费API或CLI。
4. 生图失败时按实际问题修正重试。若当前方式不可用，说明具体障碍；不偷偷用PPT形状或整页截图替代。其他API/CLI回退遵循对应工具授权规则。
5. 开始实际PPT排版前读取当前 `presentations` 技能和其所需的实现说明；需要运行时依赖时调用 `load_workspace_dependencies`。本技能规定重构方式，不硬编码随版本变化的排版API。
6. 原图保持不变。中间素材与记录放在工作目录，最终PPT及预览放在当次任务的交付目录。将选中的生图结果保存到工作目录，再嵌入PPT；不能只保留临时链接或外链。

## 0. 观察与拆解

查看原图，确定有效幻灯片区域，排除截图中的软件工具栏与外部留白。没有其他尺寸要求时，保持该区域的长宽比，不默认强制16:9。

建立内部元素清单，记录：元素编号、类型、原图坐标框、遮挡顺序、输出素材路径；文字还记录原文、换行、字体风格、字号估计、对齐、颜色与局部强调。坐标统一以有效幻灯片区域为基准。

分清四类：

| 类别 | 处理方式 |
| --- | --- |
| 整页底色、背景纹理、背景光场 | 合并为一张无字底图 |
| 独立线框、边框、装饰线与装饰箭头 | 每个独立元素一张透明图片 |
| 小插图、照片、图标 | 每个独立元素一张高清图片；需要抠出的部分透明 |
| 标题、正文、框内文字、图注与可辨识标签 | 原生可编辑文本框 |

若某幅图带有标签，把可辨识标签计入文字层，重绘图形时去除这些文字。不要将框内文字一起烘焙进线框素材。

## 1. 先提取底图

用原图作为编辑参考，去除所有需要单独重建的文字、线框、小图和图标，补全它们遮挡的背景。保留原有背景的色相、渐变方向、纹理尺度、亮暗分区和光源位置。

被遮挡区域无法从单张图真实恢复，按周围背景连续补全；不要声称提取到了原始隐藏图层。不能用大块纯色遮盖复杂纹理，也不能留下文字轮廓、框线残影或前景的重复光晕。

底图检查通过后再开始线框。生图提示词见 [references/asset-prompts.md](references/asset-prompts.md)。

## 2. 逐个高清重绘线框

逐个定位并引用原图中的线框，输出一个完整独立素材。明确原有轮廓、缺口、转角、双线关系、比例、边缘装饰及主色；只重绘该对象，去掉文字及周围元素。

重点控制：

- **光线均匀**：同一段连续线条的亮度与线宽稳定，左右/上下视觉平衡，无意外爆亮点、局部过曝、暗断口；原图明确存在的渐变或重点高光可以保留。
- **分布匀称**：重复刻度、节点、角部细节和边距有规律，保持原图设计的对称或不对称关系，不强行把非对称构图改成对称。
- **融入整页**：色相、光晕强度、锐度与底图协调，不产生白边、黑边或贴纸感。不要为了“高清”放大光效或增加荧光色。
- **真实透明**：保存带真实Alpha通道的PNG，框外透明；原图为空心的内部也透明，原有半透明面板填充则保留为合理透明度。保留柔和的半透明光晕，不把光晕切成硬边。
- **留出光晕空间**：生成画布覆盖完整外轮廓和发光外扩，不能在图片边缘突然截断。透明留白不作为可见框体定位的依据。

每个不同线框单独处理。完全相同、只重复出现的线框可复用已通过检查的同一素材，但在PPT中仍是多个独立图片对象；比例或装饰不同的线框分别生成，不拉伸同一图片凑形。

## 3. 逐个高清重绘小图和图标

逐个以原图中的小图/icon为参考，保留主体身份、轮廓、数量、方向、视角、色彩与相对细节位置，重绘到适合最终放置尺寸的清晰度。

- 孤立图标/物体输出透明PNG，完整照片保留原有矩形画幅与背景，除非原图本来就是抠图。
- 不改变箭头方向、部件数量、连接关系等有意义的结构。含可辨识文字的图先拆出文字，图形和文字分别重建。
- 对真实数据图、实验图、品牌标志，重绘不得改变数据、证据细节或标志结构。无法保证忠实时保留原图并明确记录该项例外，不把生成的细节冒充原始信息。
- 根据实际占位设定目标分辨率；优先让素材在最终预览尺寸下不需放大，条件允许时预留约2倍像素。仅放大原图不算高清重绘，不把工具未提供的分辨率称为4K。

逐个在目标底图上检查效果；确认后放到清单中的原图位置。

## 4. 还原可编辑文字

按原文逐块建立原生文本框，保留原图中的文字内容、层级、行序与颜色分布，不擅自润色、删字或更改数字。OCR只作初稿，必须对照原图校读。

- 标题、正文、图注、数字、单位以及线框内标签都应能直接点选和修改。
- 同一行不同颜色或粗细的字使用原生富文本片段；需要独立定位时可拆成多个文本框，不将文字转成PNG、SVG或轮廓。
- 字体优先使用原字体；无法确定或缺失时选择已安装的近似字体，重点匹配字重、字宽、行高。校对上下标、希腊字母、化学式和数学符号。
- 在原图对应位置匹配字号、行距、段距、文本框内边距与对齐。不要依靠自动缩小把文字挤进错误尺寸的框，不为追求大字号改动原版式。
- 含字图片不能留着原字再叠加可编辑字。去字后的素材与文本框组合后不应出现双字、残影或错位。
- 遇到实在无法辨认的字，先完成其他部分并只询问对应片段；不要猜出看似确定的内容。若用户要求先交付，列明未解决的文字，不声称所有文字已准确重建。

## 5. 组装、检查与交付

组装前及验收时读取 [references/layout-and-checks.md](references/layout-and-checks.md)，处理坐标映射、透明边距和原生文字验证。

按原图遮挡顺序放置图片及文字，通常为底图、线框/插图、文字。给对象起清楚的名字，例如 `BG_01`、`FRAME_01`、`ICON_01`、`TEXT_01`；避免整页锁成无法点选的大组。

导出PPTX后渲染成图，与原图按相同比例检查整页和局部，修正背景残影、框位偏差、光晕、图标尺度、错字、行距及溢出。检查PNG的实际透明通道及PPT中的原生文本；仅“看起来像透明”或“存在几个文本框”不等于完成。

默认交付最终 `.pptx` 和一张渲染预览。文字可编辑；图片层可独立移动、替换和缩放。只有用户要求时才额外交付素材包或内部检查记录。简短说明影响使用的真实限制，不宣称像素级一致、全部矢量可编辑或已经在未使用过的软件中验证。
