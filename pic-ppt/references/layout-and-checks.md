# 排版与验收

本文件用于实际PPT组装和交付检查。所有记录保存在工作目录，默认不占据幻灯片或备注页。

## 元素清单

用表格或JSON保存即可，不要求固定工具。至少记录：

| 字段 | 内容 |
| --- | --- |
| id / type | 唯一编号；background、frame、image、icon、text |
| source_box | 原图有效幻灯片区域中的 x、y、width、height，统一像素单位 |
| z_order | 真实遮挡顺序 |
| asset_path | 选定图片的本地路径；文本项不需要 |
| visible_box | 素材中主要可见轮廓的边界，供透明留白定位 |
| text / runs | 对照确认的文本、换行、逐段颜色与样式 |
| status | 已完成、需重绘、待确认文字等实际状态 |

文字项不要只保存OCR字符串；需要保留同一文本框内颜色或粗细切换的位置。使用原生富文本片段表达这些变化。

## 页面与坐标

设有效原图为 `W × H` 像素，PPT为 `Pw × Ph` 排版单位，保持 `Pw/Ph = W/H`。

```text
X = x / W * Pw
Y = y / H * Ph
Width  = width  / W * Pw
Height = height / H * Ph
```

若截图有工具栏或外部留白，先确定有效幻灯片区域并统一扣除偏移。不要让某些元素使用整张截图坐标、另一些使用幻灯片区域坐标。

## 透明留白与光晕

透明PNG的整张画布经常比框体大。应把可见框体对齐原图的框体，不要直接将整张PNG塞进原框的坐标框。

设素材画布尺寸为 `Iw × Ih`，主要框体在素材内的边界为 `(a, b, vw, vh)`，原图对应框体映射到PPT后为 `(X, Y, Vw, Vh)`。若宽高比例一致：

```text
s = Vw / vw                 # 同时应接近 Vh / vh
picture_x = X - a * s
picture_y = Y - b * s
picture_width  = Iw * s
picture_height = Ih * s
```

这里框体与外层柔光应分开判断：主要轮廓用于定位，全部Alpha范围用于判断光晕是否被切断。少量远处发光像素或杂点不应改变框体坐标。可读取像素与Alpha辅助分析；不要用脚本重画、抠图或修改素材来绕过生图要求。

若 `Vw/vw` 与 `Vh/vh` 明显不一致，先核查边界和原图比例；重绘有误时重新生成。不要非等比拉伸导致横竖线宽不同、圆角变形。原图确有裁切的照片可按原裁切方式放置。

## 字体与颜色

颜色需按语义段落与富文本片段逐项核对，而不是只统一成一两个主题色。优先匹配笔画主体色，勿把抗锯齿边缘或光晕误当成文字本色。

校对中文全半角、标点、数字、小数点、正负号、不等号、单位和上下标。字体替换会改变换行，应重新检查文字框尺寸、内边距和行高。不得为消除溢出删掉文字。

## 导出前后检查

### 素材

- 底图无标题印痕、旧框线或前景残留；保持原图整体明暗关系。
- 每个线框和图标有自己的素材，轮廓和细节与原图对应。
- 透明PNG确实包含透明像素与需要的半透明边缘。只检测存在Alpha通道还不够：全255的Alpha仍是不透明图。
- 分别在浅色、深色和目标底图上预览透明素材，检查格子纹、白/黑底、边缘污染和光晕截断。可直接在临时PPT/渲染器中预览，不必改写素材。
- 对称或重复部分视觉均衡，同一线条亮度稳定；重绘图片没有无依据的新文字或新部件。

### PPT结构与文字

- 图片实际嵌入文件，离开工作目录后仍可显示；每个前景元素是独立图片对象。
- 使用原生文本对象保存全部已确认文字，内容与元素清单逐项一致。不能仅凭文本框数量判断可编辑性。
- 可检查PPTX中的原生文字结构，例如 `ppt/slides/slide*.xml` 中对应形状的 `p:txBody` 和 `a:t`；检查文字的可见性、位置和层级，防止隐藏文本或透明字伪装成可编辑内容。
- 对照渲染确认显示出来的字正是原生字，图片中没有对应旧字。必要时在临时副本中隐藏/删除一个代表性文本框，再渲染检查该处是否仍有烘焙文字。
- 在临时副本中修改代表性的标题与一个含多色/上下标的文本，确认修改可见且不影响底图或框体；验证后交付原文版本。
- 页面比例、对象层序与源图一致，没有意外出界或遮挡。

### 视觉

将原图和最终PPT渲染图按相同画幅并排查看，再放大标题、密集正文、线框拐角和小图。关注：底图是否连贯、框体位置、留白、颜色分布、光效、字形、换行、文本溢出。

原图中的正确重叠不必为消除自动告警而调整。截图到重构的像素差异只能用于定位问题，不能以单一相似度分数替代人工视觉检查。

优先使用可用的PowerPoint实际渲染；只有真正打开并检查后才说“已在PowerPoint验证”。若使用其他渲染器，说明实际验证环境，仅在确有相关差异时提醒兼容性限制。

## 交付边界

默认输出一页PPTX和该页渲染预览；多张输入按用户要求逐页处理，不自行加封面。无需交付元素清单、生成提示词、验证日志或所有失败素材，除非用户要求。

只把实际完成且通过检查的对象标为完成。仍有不可辨文字、必须保留的源图或生成失败的素材时，明确对应范围；不要用“可编辑PPT”掩盖关键文本仍被烘焙的情况。
